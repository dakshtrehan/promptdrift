# Benchmark results: TF-IDF drift vs sentence-transformer embeddings

Generated by `benchmark/run_benchmark.py` with promptdrift 0.2.0 on `pairs.jsonl`: 200 sentence pairs, 100 labelled paraphrase and 100 labelled not paraphrase. See `data/SOURCE.md` for where the pairs come from.

Drift is `1 - similarity`. A good drift score is high for pairs that are not paraphrases and low for pairs that are. AUC is the probability that a random non-paraphrase pair gets a higher drift than a random paraphrase pair (0.5 is chance, 1.0 is perfect). Best-threshold accuracy is the accuracy of the single cut-off on drift that classifies the most pairs correctly, chosen on this same data, so it is optimistic.

## What the numbers mean

* TF-IDF drift reaches an AUC of 0.792 on this sample, with the best single cut-off at drift 0.315 giving 73.5% accuracy. The pairs in MRPC are drawn from news articles about the same event, so even the non-paraphrases share many words; this is a hard set for a lexical method and the AUC reflects that.
* Paraphrases average 0.250 TF-IDF drift and non-paraphrases 0.404. The two distributions overlap a lot: a faithful rewording with different vocabulary scores as drift, and a sentence that keeps the words but changes one fact (a number, a negation) scores as nearly identical. That is the known limitation of a word-overlap measure.
* The embedding leg did not run in this environment, so there is no head-to-head number here. The reason is recorded above. Anyone with the model available locally can rerun `python benchmark/run_benchmark.py` to fill it in; the script and the data are unchanged.

## What this means for promptdrift in CI

* TF-IDF drift is fine as a **cheap change detector**: when the drift between two prompt versions is near zero the outputs really are near identical, and when it is large something changed. It is deterministic, free, offline and the same on every machine, which is what a CI gate needs. That is why it stays the default.
* TF-IDF drift is **not a paraphrase detector**. A moderate drift score can be a harmless rewording or a real change of meaning, and this benchmark shows it cannot tell those apart reliably. Do not set `--max-drift` tight and expect it to catch only real regressions.
* For meaning, use the signals built for it: deterministic `checks` (regex, JSON keys, exact) for facts that must hold, multi-sample noise floors to see how much drift a prompt produces against itself, and the judge or embeddings (`--similarity embedding`) when a semantic score is worth the cost. Embedding scores are on a different scale from TF-IDF, so thresholds do not carry over between them.

## Caveats

* 200 pairs is small; AUC differences of a few hundredths are within noise.
* Best-threshold accuracy is picked on the same data it is scored on.
* MRPC sentences are news text. Prompt outputs (JSON, lists, code) behave differently, and promptdrift adds structural drift and checks for exactly that.
* The sample is rebalanced to 50/50; the full MRPC test split is 68 percent paraphrases.
